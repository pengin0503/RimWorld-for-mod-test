# ゲーム起動不要の入力監査ツール

ユーザーの「Linux 版なしで進められる作業があれば進めて」という依頼に基づく、入力受け入れの補助ツール。既存の公式 headless＋観測 MOD の設計は変更しない。

Python 3.12 以上、標準ライブラリのみ。`tools/audit_inputs.py` に `zip` と `metadata` のサブコマンドを設ける。ZIP を展開せず読み、CRC・SHA-256・パス衝突・リンク・XML 構文を調べる。必要なら manifest の指定ディレクトリと照合する。metadata は manifest と textures.info の形式・パス集合を照合する。

候補は受領時の一時スクリプトを継続する方式と、再利用できる補助 CLI にする方式。後者を今回の判断として採用する。ゲーム API を呼ぶ独自ローダーは既存の合意と異なるため採用しない。ゲーム本体をロードせず、未実装のランチャーや観測 MOD をこの作業へ混ぜない。

結果は `recordType=offlineInputAudit`、`schemaVersion=1`、`gameVerification=notRun` を固定し、静的検査の `auditStatus` と区別する。検査エラーは `failed`、未対応圧縮方式・上限到達・不確かなファイル名は `incomplete`、要求した静的検査が通った場合だけ `passed`。CLI 終了コードは順に 1、2、0。ゲームによる合格、完全なインストール、フォントの描画、アセットのデコード、入れ子 ZIP/TAR 内の検査は主張しない。

ZIP の総エントリ上限は 100,000、展開後の累積読出しは 512 MiB、単一エントリは 256 MiB、診断は 200 件。サイズ上限は CLI で変更可能。XML はストリーミングの Expat を使い、DOCTYPE を拒否する。metadata ファイルは各 16 MiB まで。入力を上書きせず、出力先が入力自身なら拒否する。ネットワーク、ゲームファイルの CI アップロード、実行・抽出は行わない。

レビュー後の判断：Stored/Deflate だけを独立デコードし、圧縮終端・展開サイズ・CRC を照合する。zipfile の宣言サイズに依存した読み出しだけでは過小な宣言値による切捨てを見逃すため。LZMA 等は安全な検査を実装するまで `incomplete` とし、破損の有無も断定しない。

自作の小さな ZIP・XML・manifest fixture だけでテストする。実受領ファイルでの確認結果は非公開に保存し、公開するのは集計値のみ。公開 CI も自作 fixture と構文検査だけを実行する。
