# ヘッドレス起動の試運転レポート（2026-10-25）

この試運転で作ったコードは使い捨てで、リポジトリには入れていません。

## 結論
Linux（このクラウド環境）の標準 .NET 10 で、Windows版から取ったゲームの .NET DLL を使って公式の `-headless` 起動を行い、**ゲーム本来の Defs 読み込み処理が Core の XML を解析するところまで到達**しました。A（読み込み検証）は実現できる見込みが高いです。

## 動かすために自前ランチャーでやったこと
- ヘッドレスを強制する（画面・入力・GPUを作らない）
- 無音の音声バックエンドに差し替える（Linux用の音声ライブラリが不要になる）
- `UnityEngine*` の参照を `UnityStubs` に読み替える（公式ランタイムの設定と同じ内容）
- Steamライブラリが無いとゲームが終了するので、その確認処理だけ飛ばす（Steam未起動でも動く作りなので、ゲームの所有確認を回避するものではありません）
- ランチャーをゲームフォルダに置いて起動する（ゲームは実行ファイルの場所からインストール先を判断するため）

## 止まった理由と、まだ足りないもの
| 足りないもの | 影響 |
|---|---|
| インストール先の `Rendering/Shaders/`（GLSLのテキスト） | 素材の初期化が失敗し、それに連鎖して多くの Def の生成が失敗した |
| 完全な `Data/` フォルダ（最初のzipは Defs/Patches/Languages/About のみ） | テクスチャ・音などの参照エラーが出る |
| `Assets.zip`（Core 358MB、DLC合計約350MB） | 無い場合は `-NoAssetPack` で起動はできるが、テクスチャのエラーを正しく判定できない |
| Harmony MOD（公式には含まれない。MITライセンス） | B の検証に必須。公開されているので入手できる |

## 重要な発見：公式は独自の .NET ランタイムを使っている
Windows版には `WaylithClr` という改造版 .NET ランタイムが同梱されています。設定から、例えば次のような違いがあることが分かりました。
- Assembly-CSharp のメソッドをインライン化しない（Harmony パッチが確実に効くようにするため）
- アセンブリの読み込みや型の解決を緩くしている
- 文字列のハッシュを Mono 互換にしている

標準 .NET ではこれらが再現されないため、**特に B（Harmony）で「実ゲームでは効くパッチが効かない／逆も起こる」恐れ**があります。Linux版のインストールには Linux用の WaylithClr と Steam ライブラリが入っているはずなので、それを使えばこのずれを無くせます。

## その他
- エラーが毎フレーム出続けてメモリを約14GBまで使い、強制終了されました。本番のツールには、ログの上限・タイムアウト・メモリ監視を入れます。
- 最初の `rimworld_DLL.zip` は別々のビルドが混ざっていました。後から送ってもらった3分割のzipは、同じ時点の一式で揃っています。
