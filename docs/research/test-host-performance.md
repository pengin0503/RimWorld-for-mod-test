# 検証ホストの所要時間

測定日：2026-10-25。環境：Claude のクラウド Linux x86_64 コンテナ（4 vCPU、メモリ 15 GiB、ローカルディスク）、RimWorld 1.7.4985 rev1269、WaylithClr 10.0.13。測定スクリプト：`experiments/performance/measure.py`（開発用）。各条件 5 回で、中央値と範囲を示す。

**全て warm キャッシュでの値です。** コンテナでは OS のファイルキャッシュを消せないため、cold start の値はありません。ユーザーの PC から最初にファイルを受け取る時間（ネットワーク次第）も含みません。

## 結果

| 測定 | 内容 | Core＋対象 MOD（英語） | Core＋4 DLC＋対象 MOD（日本語） |
|---|---|---|---|
| 準備 | `prepare-game`：約 1.0 GB のコピー、全 SHA-256、読み取り専用化（1 回目だけ必要） | 4.2 秒（3.9–9.7） | 同左 |
| 1 回の検証（キャッシュなし） | `run` 全体：スナップショット照合、ベースラインと対象の 2 回の Worker、判定 | 16.8 秒（15.8–17.5） | 27.7 秒（26.5–29.9） |
| 1 回の検証（ベースラインのキャッシュあり） | 同じ構成の 2 回目以降。対象の Worker 1 回だけ | 8.8 秒（8.0–9.3、n=4） | 14.0 秒（13.0–16.1、n=4） |
| Worker 単体 | 対象 Worker プロセスの起動から終了まで | 8.3 秒（7.5–8.9、n=10） | 14.1 秒（12.7–15.8、n=10） |
| 参考：公式 headless | 公式実行ファイルを `-headless -QuitAfterBoot` で、同じ MOD・設定で起動（開発用の比較で、製品は使わない） | 8.8 秒（7.7–9.1） | 13.6 秒（13.2–16.1） |

準備の 1–2 回目（9.0、9.7 秒）は、コピー元がまだページキャッシュに載っていなかった影響とみられる。原因を切り分けてはいない。キャッシュありの 1 回目はキャッシュを作る実行で、キャッシュなしと同じ時間になる。そのため中央値の計算から除いた。

## 読み方

- 1 回の Worker は、同じ範囲を読み込む公式 headless 起動とほぼ同じ時間です。差は測定のばらつきの範囲内でした。**独立ホストにしたことで読み込みが速くなったわけではありません。** 時間の大半は実際のゲームの読み込み（XML、Def、翻訳、公式の Def 検査、アトラス）です。
- 検証 1 回あたりの時間は、ベースラインを毎回取るとほぼ 2 倍になります。同じ構成で修正と再検証を繰り返すときは、`--baseline-cache` で Worker 1 回分に減らせます。
- 範囲：A（実ローダー、公式の DevMode Def 検査を含む）と、要求すれば B。C/D は含まず、マップ生成や tick の時間はかかりません。
- **公式の通常（GUI）起動との比較はしていません。** クラウドには画面と GPU がなく、メインメニューまでの時間や描画の初期化を同じ条件で測れないためです。「通常起動より速い」とは主張しません。Windows の利用者環境での測定も未実施です。
- 公式 headless は製品の代わりになりません。比較の参照値として載せているだけです。
